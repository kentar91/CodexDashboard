## Problems and ideas

Open an [issue](https://github.com/kentar91/CodexDashboard/issues/new/choose) using an Italian or English template. For a bug, include the version, reproduction steps, expected result and observed behavior. For a request, explain the need and an example use case. Check existing issues before opening a new one.

Do not attach tokens, API keys or authentication files. Review screenshots and diagnostics for personal details before sharing them.

## Source changes

For larger changes, describe the proposal in an issue first. Keep pull requests focused on one problem and explain how you verified the result.

- Work in `src` and `assets`; `build` and `dist` are generated.
- Update Italian and English together in affected interfaces and documentation.
- Follow the [design and palette](docs/DESIGN.en.md), preserving readability and large percentages on keys.
- See [building](docs/DEVELOPMENT.en.md) and [verification](docs/VERIFICATION.en.md). Run checks relevant to the change; for visual changes, check previews in both languages.
- Explicitly identify hardware or post-reboot checks you have not performed.

Proposals are reviewed by the author. Contributions to the project retain the MIT license.
